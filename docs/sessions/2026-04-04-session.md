## 5. AR Explorer — Captura Rápida

**Archivos clave:** `features/ar/index.js`, `features/ar/ar.html`, `features/ar/ar.css`, `features/ar/controllers/*`, `js/engines/AIEngine_YOLO.js`, `js/services/CaptureQueue.js`

### Quick Capture (⊕)
- Botón circular centrado 64px, 1-tap captura instantánea
- Enqueue a CaptureQueue (0ms, sin network)
- Flash visual 150ms + counter HUD

### CaptureQueue (NUEVO)
- `js/services/CaptureQueue.js` — cola persistente en localStorage
- Batch processing: 5 items cada 800ms via `POST /api/captures/batch`
- Fallback a `/api/captures/process` individual
- Notificaciones silenciosas (solo errores y re-IDs como popup)
- Sobrevive fin de misión y navegación

### Sentinel Refactorizado
- Cooldown por individuo (`track_id` de ByteTrack), no por clase
- Captura TODAS las entidades del frame simultáneamente (max 5)
- Crop individual via bbox YOLO + 15% padding
- Skip crops < 500 bytes
- Toggle 🛡️ movido al action hub (no solo en settings)
- Unificado: Sentinel + AutoSave en un solo toggle

### FPS Dinámico
- Exploración: 333ms (~3 FPS) — default
- Enfoque: 100ms (~10 FPS) — auto cuando target lock
- Reposo: pausado — cuando HUD oculto + Sentinel off
- Auto-switch basado en target y estado del HUD

### HUD Auto-Hide
- Top/bottom bar + telemetría se ocultan tras 10s
- Tap en pantalla los muestra 10s más
- Quick Capture (⊕) y counter siempre visibles

### UI Compacta
- Botones solo-icono 48px (AI, Scan, Teach, Tick)
- Quick Capture centrado prominente
- Sentinel en hub con pulso rojo cuando activo

### ByteTrack (Backend)
- `inference.py`: `model.track(persist=True)` → `track_id` persistente
- Dependencia: `lapx` instalado + agregado a requirements.txt

### WebSocket Mobile
- URL dinámica: `${wsProtocol}//${window.location.host}/api/ws/detect`
- Vite proxy `/api` con `ws: true`

## 6. Backend — Capture Processing

**Archivos clave:** `backend/app/api/endpoints/captures.py`, `backend/app/main.py`

- `POST /api/captures/process` — procesar captura individual
- `POST /api/captures/batch` — procesar batch (5 items)
- Pipeline: CLIP embedding (50ms GPU) → Re-ID pgvector → DB insert
- Re-ID automático para persona/poi/generic (threshold 0.78)
- Sin Ollama enrichment en pipeline crítico (velocidad)
- Imágenes guardadas en personas (`image_url`) y POIs (`image_url`)
- Embeddings generados en background para todas las entidades

- `05_persona_identity.sql` — campos `rasgos_fisicos`, `hostilidad`

## 9. Fixes de Errores

| Error | Causa | Fix |
|---|---|---|
| `/api/api/explorer/stats` 404 | Doble prefijo /api | URL corregida en sidebar.js |
| `/api/dashboard/stats` 401 | Sin token auth | Agregado Bearer token |
| Sistema status "Backend error" | Endpoint con auth | Cambiado a `/health` |
| `misiones` 400 | Columna `created_at` no existe | Cambiado a `inicio_at` |
| ipapi.co CORS/429 | API externa con rate limit | Proxy backend `/api/utils/geolocate` con cache |
| GPS permission prompt | Sin feedback al usuario | Hint visual + navigator.permissions check |
| Mapa vector flash | Carga raster primero | Pre-load vector style antes de crear mapa |
| YOLO "No module lap" | ByteTrack dependency | `pip install lapx` + requirements.txt |
| Capture 422 | `location.source` (string) en Dict[str, float] | Solo enviar `{lat, lng}`, backend acepta `Dict[str, Any]` |
| Captures errores intermitentes | Crops vacíos/corruptos | Skip < 500 bytes, clean base64 prefix, embedding condicional |
